# TOEFL Study App

A static study site for TOEFL-style reading. You answer the questions, click any word you
do not know to read an English note on it (etymology, definition, role in the passage,
related words), and add it to Anki on the spot. The site is served from GitHub Pages, has
no backend, and visitors need no API key.

> ⚠️ **Disclaimer**: every passage, question and explanation is generated by AI and has
> not been reviewed by an expert. The author is not a specialist in English teaching.
> This is unofficial study material and is not affiliated with ETS or TOEFL.

## Features

- **Solve mode**: the format of the real TOEFL (the passage on the left, one question at a
  time on the right). The elapsed time counts up. On the public site the result is saved
  in the browser's localStorage
- **Study mode**: every word is clickable. A listed word shows a full English note and a
  button that adds it to Anki; an unlisted word shows a link to Cambridge Dictionary. The
  English explanation of each question is shown too
- **Anki integration**: adds a card to Anki on your computer with one click, through
  AnkiConnect (the setup steps are on the site's "Guide" page)

## Checking it locally

```bash
python3 -m http.server 8000 -d docs
# open http://localhost:8000/
```

Opening `docs/index.html` directly as file:// makes fetch fail, so always go through a
local server.

## Adding a passage (for developers)

Run `/new-passage` in Claude Code. Claude generates the passage, the quiz and the
vocabulary notes, and runs the steps below (no Anthropic API key is needed; it runs within
the Claude Code subscription):

1. Generate `docs/data/reading/passage_NNN.json`
2. `python3 scripts/extract_hard_words.py <file>` — extract the hard vocabulary
3. Merge the English notes on the hard vocabulary into `vocab`
4. `python3 scripts/validate_passage.py <file>` — validate the schema
5. `python3 scripts/update_index.py reading` — rebuild the index

One script rebuilds every index: `python3 scripts/update_index.py [skill ...]`, where a
skill is `reading`, `listening` or `writing`. With no argument it rebuilds all 3
(`docs/data/<skill>/index.json`).

## Local app (macOS / Linux)

A native app that does not depend on a browser (`app-shell/`, Rust + tao + wry), made to
carry study features such as listening and writing. It keeps the study records as real
files.

```bash
bash app-shell/build.sh    # build (cargo only)
TOEFL_REPO_ROOT="$(pwd)" app-shell/target/release/app_shell
```

On macOS, `sh app-shell/install-macos.sh` puts a double-clickable launcher,
`TOEFL Study.app`, into `/Applications`. It starts the binary built in this repository, so
the repository must stay where it is; run the script again after moving it.

### Before building on Linux

Install the system libraries that wry (WebKitGTK) and tao (GTK3) need first.
Confirmed on Ubuntu 24.04:

```bash
sudo apt install -y pkg-config libgtk-3-dev libwebkit2gtk-4.1-dev \
  libsoup-3.0-dev libjavascriptcoregtk-4.1-dev libdbus-1-dev libxdo-dev
```

Without them `cargo build` stops with a `pkg-config` error for `dbus-1` or `gobject-2.0`.
Confirmed to work on GNOME in an X11 session (Wayland is untested).

- Reading attempts are **appended** to `attempts.jsonl` (never overwritten). The data
  directory is `~/Documents/TOEFLReading/` on macOS and `~/.local/share/toefl-reading/`
  on Linux
- Passages are read from disk at every start, so a passage added with `/new-passage`
  appears **without a rebuild**
- The repository root is given by the environment variable `TOEFL_REPO_ROOT` (when it is
  not set, the current directory at start-up is used)
- macOS and Linux are supported (Windows is designed for but untested). The binary is not
  signed, so it is not suited to distribution (it assumes personal use)
- Listening is in the local app only, and **its audio does not work yet**. The `speech`
  handler in the Rust app is a placeholder that always returns an error
  (`app-shell/src/ipc/placeholder.rs`), so no audio is generated or played on either
  platform. Listening items (`docs/data/listening/`) can be opened, and after the audio
  error the script can be reviewed, but they cannot be listened to. New items are added
  with `/new-listening`

The public site (GitHub Pages) has reading only, and its records stay inside the browser.

## Writing

Local app only. There are 2 formats: an email task (TOEFL Essentials style: read a
situation and write a reply of 6-10 sentences to the recipient) and an academic discussion
task (a professor's post and replies from 2 students, to which you add your own opinion).

Grading goes through the `claude` CLI that comes with Claude Code. No Anthropic API key is
needed. If Claude Code is installed and logged in, the grade button in the local app
starts it. Grading usually takes about **16-22 seconds**, but it can take much longer and
occasionally fails on a network error; the app gives up after 180 seconds. For that
reason the app saves the essay before grading and, on failure, shows a screen from which
you can grade it again. The feedback is written in English.

Essays are only ever **appended** to `essays.jsonl` in the data directory above. A
regrade is appended as a separate line, and the value of `gradedAt` decides which grade is
the latest. On macOS the path is:

```
~/Documents/TOEFLReading/essays.jsonl
```

To add a prompt, run `/new-writing` in Claude Code. The data is saved in
`docs/data/writing/`, and the local app reads it without a rebuild.

Where the `claude` command is not on PATH (for example an `.app` started from Finder,
which sees only `/usr/bin:/bin:/usr/sbin:/sbin`), set the environment variable
`TOEFL_CLAUDE_BIN` to its full path when starting the app:

```bash
TOEFL_CLAUDE_BIN=/path/to/claude TOEFL_REPO_ROOT="$(pwd)" app-shell/target/release/app_shell
```

## Public URL

https://shutouyusei.github.io/english_reading/

To use the Anki integration on the public site, add `https://shutouyusei.github.io` to
`webCorsOriginList` in AnkiConnect (the steps are in
[Guide: Setting up Anki](https://shutouyusei.github.io/english_reading/guide.html#anki)).

### Forking it to publish your own copy

1. Create a repository on GitHub and push
2. In Settings → Pages, choose Branch: `main`, Folder: `/docs`
3. Change 2 places in `docs/guide.html` to your own URL
   - `https://shutouyusei.github.io` in the Anki setup steps (the origin of the site that
     visitors must allow)
   - the Issues link `https://github.com/shutouyusei/english_reading/issues` in the
     disclaimer section
4. Add `https://<your user name>.github.io` to `webCorsOriginList` in AnkiConnect
